Shortest Path and Route Optimization

Finding the cheapest way through a network is a graph problem. This page implements three shortest-path algorithms and two route-optimization heuristics, and lets you run each one on your own data.

Objective

Model a map as a weighted graph G = (V, E, w) and compute (1) the minimum-cost path between two vertices, and (2) a short closed tour that visits every city once. We compare BFS, Dijkstra and A* by the number of nodes each explores, and compare nearest-neighbour with 2-opt improvement by tour length.

Mathematics

Dijkstra

Settles the vertex with the smallest known distance, then relaxes its edges. Requires w ≥ 0.

d(v) ← min( d(v), d(u) + w(u,v) )

A*

Orders vertices by estimated total cost. With a consistent heuristic h it returns the same optimal path while exploring fewer vertices.

f(v) = g(v) + h(v)

2-opt

Removes edges (a,b) and (c,d), reconnects as (a,c) and (b,d) when that shortens the tour, and repeats until no swap helps.

Δ = d(a,c) + d(b,d) − d(a,b) − d(c,d) < 0

The grid demo here uses a simple scan to pick the next vertex (O(V²)), which is fast enough for 512 cells; a heap is the standard choice for large graphs.

Conclusion

Dijkstra and A* both find minimum-cost paths, and A* explores far fewer cells because the heuristic points it at the goal. BFS finds the fewest steps, which is not the cheapest route once terrain has different costs. For the route problem, no fast algorithm is known that always finds the best tour, so heuristics such as nearest neighbour plus 2-opt give a good answer quickly.
